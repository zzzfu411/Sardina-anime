这些修改新增 11 项回归测试。设置冲突、备份版本回退和时间精度问题先以失败测试复现，再验证修复。解析耗时是这台机器的单次受控样本对照，不是跨机器性能保证。详见 [解析测量](parser-performance.json) 与 [安全问题细节](FINDINGS-DETAIL.md)。

`engine-startup.sqlite` 是跨进程互斥载体，可能为空文件；必须保留，不能当作旧锁删除。它不保存用户内容。旧版程序尚不使用这一互斥文件，正常旧实例仍受原有 PID/锁检查保护；不建议同时启动不同版本抢占同一资料目录。

## 对你已有修复的复核

- 鉴权依据匹配后的 API 路由，编码路径别名和自动 HEAD 路由也会验证令牌。独立内存审查覆盖全部 41 条 API 的 142 个未认证请求，以及 8 组 Host/Origin/fetch-site 检查；未认证请求被拒绝，有效 Cookie/Bearer 可使用。
- 媒体 HTTP 403 等错误写入来源健康和诊断；416 与主动取消不应被当作来源故障。来源允许主机列表由适配器提供。
- 大备份恢复路由与导出的上限为 64 MiB；新增约 18 MB、600 条合法历史记录的导出/恢复 API 往返测试，覆盖旧 16 MiB 限制。
- 精确单集进度读取、设置 revision 冲突检查、来源设置部分更新、显式详情刷新、请求取消与播放器方向键功能保留，并参与最终回归。

## 安全结论与依赖

交付树中上述已确认解析问题已修复。[findings.json](findings.json) 记录的是基线中已确认、现在已修复的问题；其原始代码留在 [基线快照](protobuf-before.txt)，不是仍然存在的漏洞。审查过程分离了来源解析、访问控制及生命周期复核，并对解析问题做了独立否证和修复复核。

本项目采用单用户本地资料模型，类似 FreeTube 的本地资料与远端内容分离方式；不将同一资料库的认证客户端视为不同租户。[FreeTube 官方 FAQ](https://docs.freetubeapp.io/faq/) 可作为部署模型参照，未验证 FreeTube 使用相同二进制解析器。Electron 禁用 Node integration、开启隔离与沙箱，并限制导航，符合相关 [Electron 官方安全指引](https://www.electronjs.org/docs/latest/tutorial/security)。

原审查的生产依赖检查报告了 `@fastify/static@8.3.0` 的四条通告。已阅读维护者通告并核对当前配置：未开启目录列表，也未用静态文件的私有子目录或 allowedPath 作为鉴权边界，因此没有据此确认本项目可利用的数据泄露。分别见 [目录列表](https://github.com/fastify/fastify-static/security/advisories/GHSA-pr96-94w5-mx2h)、[编码分隔符](https://github.com/fastify/fastify-static/security/advisories/GHSA-x428-ghpx-8j92)、[路径归一化](https://github.com/fastify/fastify-static/security/advisories/GHSA-83w8-p2f5-377r) 和 [allowedPath](https://github.com/fastify/fastify-static/security/advisories/GHSA-8pvw-jcv7-9cmj)。通告的受影响依赖仍在，建议单独安排兼容性升级与桌面打包验证；本轮未升级主版本。

正向保护包括：仅监听回环地址、随机令牌、Host/Origin 校验、HttpOnly/SameSite Cookie、参数化 SQL、备份验证与事务恢复、公开地址/DNS/重定向检查、媒体资源登记、React 文本转义和 Electron 沙箱。本轮未发现这些路径上的新可利用问题。

## 后续优化顺序

1. **来源诊断补齐网络层错误**：现有媒体健康记录主要覆盖 HTTP 错误码；连接超时、DNS 失败及流中断也可统一记录，避免“解析成功”掩盖后续播放故障。
2. **追番更新有限并发**：当前批次和条目按顺序读取，慢来源会拖延整库刷新。可在维持同源节流、可取消和保存前重读的前提下，引入少量并发。
3. **封面请求复用**：浏览器有缓存，但网关本身没有共享进行中的图片读取；多窗口同时打开相同封面会重复上游请求。可按登记图片 ID 复用并设置字节上限。
4. **维护性与打包**：播放器已按需加载，但仍有约 607 kB 的压缩前播放器块和较大的页面模块。建议根据实际首播时间再拆分模块，并在依赖升级时重跑 Safari、桌面安装包及真实来源整集验证。

这些是后续优化建议，不列为本轮未解决的安全漏洞。现有用户界面、来源选择和视觉主题保持原有设计。
