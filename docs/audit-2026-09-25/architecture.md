# Sardina anime：审查续接架构（2026-09-25）

Target: Sardina anime, working tree v0.7.0 including existing local fixes. This continues an earlier audit that produced architecture notes and isolated reproductions, but no final findings.json.

Sardina anime is a single-user local anime player. React 19 / Router 7 / TanStack Query 5 / hls.js talk to a Node 24 / Fastify 5 / SQLite engine. Electron 41 forks that engine. Seven bundled adapters (girigiri, AniCh, Aki, erkuang, gugu, ledou, xifan) and Bangumi receive remote data. No accounts, tenants, dynamic plugins, renderer IPC, OAuth, or remote JS execution. Baseline: FreeTube's local-profile/remote-content model and Electron security guidance. All authenticated clients own the same profile.

runtime.ts binds 127.0.0.1 on a random port, generates a 32-byte token, writes 0600 engine state, and uses exclusive profile locks plus authenticated health for reuse. Current fixes check app version, request authenticated shutdown on mismatch, and recover stale empty/malformed locks. CLI environment/file paths are controlled by the local owner. server.ts applies strict Host/Origin checks and a preHandler token gate based on the matched routeOptions.url, replacing the old vulnerable raw URL prefix gate. /bootstrap sets an HttpOnly SameSite=Strict 30-day cookie. CSP is same-origin, no CORS, frame-ancestors none. Static UI is public.

HTTP APIs cover discovery/search/CAPTCHA, details/ratings/Bangumi links, playback/media/images, library/history/settings, backup/restore, cache/diagnostics, and authenticated shutdown. Default body limit is 16 MiB, backup restore now 64 MiB matching export size checks. Zod validates inputs. Store uses bound SQL, WAL, transactional migrations/restore and fixed backup filenames. Settings now have revision conflict checks. History now requires capturedAt and can be fetched by episode key. Source settings accept partial changes.

http.ts enforces public HTTP(S) addresses, DNS validation/pinning, restricted ports and redirect revalidation, stripping sensitive headers across origins. Environment proxies are trusted. Cookies are scoped per source/search session. Adapters parse HTML/JSON/JSON5/AES/Protobuf without eval. Media is registered by session/resource IDs with resource and byte caps, HLS URI rewriting and Range support; images accept raster MIME. Resolved media now supports adapter-provided host allowlists, and HTTP media failures update diagnostics. Search CAPTCHA uses bounded expiring user-entered sessions.

React renders escaped text and local registered media/image URLs. Electron disables Node integration, enables sandbox/context isolation/webSecurity, restricts navigation/window creation. Test-only fixture overrides in tests/e2e-server.ts are excluded from builds. Current web fixes include cancellation signals, settings conflict retries, history sampling timestamps, explicit detail refresh and keyboard shortcuts.

Earlier isolated findings: encoded API path could bypass authentication (now fixed; verify); stale full settings writes; history arrival reordering; export over 16 MiB could not restore; media 403 missing health diagnostics; old engine version reuse; stale empty lock; library serial refresh and duplicated image reads. Functional defects must be separated from security vulnerabilities. The user has already addressed many of these; assess the current tree, preserve their work.

Do not touch actual user profiles or live browser/server. Use in-memory databases and isolated fixtures only. No source restrictions, paid gates or CAPTCHA protections are to be bypassed. Security findings need concrete boundary crossing and meaningful impact; do not inflate local-owner operations or defense-in-depth notes into vulnerabilities.
