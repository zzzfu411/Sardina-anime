# v0.3.1 请求性能与首选来源

检查日期：2026-09-23，当前 Mac、Node 24、Chrome 153。新资料库默认优先 girigiri；用户保存的启停和排序仍然有效。首页推荐、无指定来源的索引和周期表按已启用来源的顺序选择。

## 已实现的优化

- 首页先请求当前推荐来源，默认 girigiri。可通过“推荐来源”下拉切换其他来源；聚合搜索仍查询所有已启用来源。原来启动首页会同时读取七个推荐来源，现在读取一个，减少请求排队和无关海报加载。
- 首页推荐和周期表共用 girigiri 首页的一次读取；同一分钟内切换星期复用已读取的页面，日期显示实际读取时间。
- 目录、搜索、详情、推荐和周期表的相同并发请求合并。一个页面退出时只取消自己的等待；最后一个读取者退出才取消上游。取消不会被显示为来源故障。
- 元数据结果缓存五分钟，按最近使用淘汰，最多 500 项。girigiri 原始首页另外保留一分钟，叠加后目录数据可能延迟约六分钟。手动刷新绕过这两层缓存；清缓存同时使网页的推荐、索引、周期表和详情查询失效，旧请求不会重新写回已清空的缓存。
- 代理模式下，API、HTML 和封面读取复用连接。连接池按代理、站点 origin 和已检查 IP 隔离，每次请求仍重新验证 DNS，IP 变化时使用不同连接池。每个来源最多保留 32 个池，仅淘汰闲置池，不切断活跃读取。
- 网页数据请求使用较高的浏览器调度优先级；海报懒加载并异步解码。

## 验证与范围

固定样本 124 项、浏览器 12 条流程通过，覆盖并发请求、单窗口取消、全部取消、清缓存后的旧响应、强制刷新、DNS 变更、请求超时，以及首页按需切源和返回缓存。girigiri 两集再次完成真实起播、90 秒拖动和续播，最大续播误差约 0.024 秒，见 [播放复查](validation/performance-playback.json)。本轮没有重复执行整集或 Safari 验证，历史整集证据见 [验收记录](VALIDATION.md)。

这次优化针对目录、页面和请求排队。首次访问仍依赖来源响应，视频缓冲还取决于上游 CDN 与本机网络。girigiri 关键词搜索仍受站内验证码限制，公开索引与周期表可直接使用。
