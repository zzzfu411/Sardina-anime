# 评分与热门内容

v0.7.0，2026-09-24。详情页分别展示来源分数和 Bangumi 官方接口数据，不将不同口径平均成一个分数。

## 数据依据

| 内容               | 读取位置                                                                        | 展示口径                                                                                   |
| ------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| girigiri 站内评分  | 详情 `.play-score .fraction`、`.text-site`                                      | 10 分制站内投票与人数；站点脚本将五颗星乘 2 提交                                           |
| girigiri「番」分数 | `.douban-score .score`；部分列表的 `.public-list-prb i.ft4`                     | 标为 girigiri 展示分。页面没有对应外部条目 ID，不能视为实时 Bangumi 官方评分               |
| 稀饭收录分数       | `get_anime_detail` / `search_animes` 的 `bangumi_score`、`bangumi_rating_total` | 标为「Bangumi · 稀饭收录」，保留来源快照与官方数据的区别                                   |
| Bangumi 官方评分   | `POST https://api.bgm.tv/v0/search/subjects`、`GET /v0/subjects/{id}`           | 动画条目的 `rating.score`、`rating.total`、`rating.rank`；附原条目链接、匹配方式和获取日期 |

仓库研究响应 `.cache/reverse-audit/xifan-search.json`、`xifan-detail.json` 保留了稀饭字段，前端分块还引用 `lain.bgm.tv` 封面。没有把 AniCh 自有 `/bangumi/*` 接口误当作官方 Bangumi API。原始研究响应不进入安装包；测试使用最小固定样本。

官方接口依据：[OpenAPI 定义](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)、[User-Agent 约定](https://github.com/bangumi/api/blob/master/docs-raw/user%20agent.md)。引擎设置 `zzzfu411/Sardina-anime/<版本>` User-Agent，并附公开仓库地址；只访问 `api.bgm.tv` 的公开接口，不使用解包应用的账号凭据。

## 条目匹配与保存

1. 用户此前确认的关联优先，按「来源 ID + 来源条目 ID」保存。
2. 有明确 `externalIds.bangumi` 时按 ID 读取；已知年份、形式、季度冲突则要求确认。
3. 没有 ID 时搜索动画条目；只有完整候选集中的唯一候选、片名/别名精确匹配，且年份、形式、明确季度一致时自动关联。缺失资料、同名、多篇章合并、截断候选集均不猜测。
4. 页面可按片名查找，或输入官方条目编号/链接；先预览标题、日期、形式，再点击「选这部」。可以更改或取消手动关联。不会因为手动选择一个评分条目就合并播放源、追番或剧集。

例如 girigiri 的 Re:Zero 第四季把丧失篇与夺还篇合在一个条目，Bangumi 则有两个条目。这里需要用户选择当前篇章，不能随便取搜索第一项。girigiri 未提供可确认形式的条目也会保留候选，供人工确认。

新关联存放在已有 SQLite `settings` 表的 `bangumi-links` 键；无需数据库结构迁移。JSON 备份 v1 增加可选 `bangumiLinks`，旧备份可正常恢复。恢复旧备份时清空旧的评分关联，避免把当前关联带入另一份资料；重复、非法 ID 在恢复前拒绝。

## 性能与故障

来源已有分数随详情显示；Bangumi 单独请求，不阻塞选集和播放。请求合并、最多 400 项的六小时内存缓存、每次网络请求八秒截止时间，以及调用者独立取消机制减少重复访问。手动关联持久化，缓存不进入备份。关闭或清缓存会清理评分缓存；清缓存不会删除手动关联。

无评分、零票、非法分数不伪装成 `0.0`。Bangumi 不可用时显示重试与手动查找入口，不改变播放源的健康状态。站点快照可能滞后于官方分数，分别标注。

## 热门与高分入口

- 发现页加入 girigiri 原有「最近大家在看」，与周期表共用同一次首页响应，不增加主页网络请求。
- 「热门与高分」进入按来源浏览的目录；默认按来源热度，支持切到来源评分和最近更新。当前 girigiri、AkiAnime、乐豆有真实热度/评分排序；咕咕提供最热和最赞，最赞不等同于评分。
- 快捷排序保留年份、题材等当前筛选；切换来源清除不支持的筛选，重置页码，再使用新来源的排序值。翻页和返回保留 URL 中的条件。
- 没有公开统计周期，不称为日榜、周榜或实时榜。来源评分排序与 Bangumi 官方条目排名是不同数据，没有合成跨来源排行榜。

真实网络记录见 [评分与热度检查](validation/ratings-live.json)。girigiri、AkiAnime、乐豆、咕咕和 Bangumi 本轮返回有效数据；稀饭本轮公开入口为 HTTP 401，其字段解析通过固定样本测试，但不声称当前来源可读。未进行投票、登录或 CAPTCHA 自动识别。
